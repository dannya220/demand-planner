# Данные проекта

Источник: [M5 Forecasting — Accuracy](https://www.kaggle.com/competitions/m5-forecasting-accuracy/data).
Для загрузки используется [копия на Zenodo](https://zenodo.org/records/12636070).
MD5 архива: `86f57416a314197f40a17cc6fc60cbb4`.

## Три исходные таблицы

| Файл | Что хранится |
| --- | --- |
| `sales_train_validation.csv` | Количество проданных единиц по дням; одна строка — товар в магазине |
| `calendar.csv` | Даты, номера дней и недель, календарные события и индикаторы SNAP |
| `sell_prices.csv` | Продажная цена для пары товар-магазин за неделю |

## Наша первая выборка

- Категория: `FOODS`.
- Товаров: 100.
- Дней на товар: 1913.
- Период: 2011-01-29 — 2016-04-24.
- Строк в длинной таблице: 191,300.
- Товары выбраны случайно с seed 42 из отсортированного списка идентификаторов. Их будущие продажи не использовались для отбора.

Подготовленная таблица: `data/processed/m5_ca1_foods_100.parquet`.
Список товаров: `data/processed/selected_items.csv`.
Результаты проверки: `data/processed/summary.json`.

## Основные столбцы подготовленной таблицы

| Столбец | Значение |
| --- | --- |
| `date` | Дата наблюдения |
| `item_id`, `store_id` | Идентификаторы товара и магазина |
| `dept_id`, `cat_id` | Отдел и категория товара |
| `sales` | Наблюдаемые продажи в единицах за день |
| `sell_price` | Продажная цена за соответствующую неделю |
| `price_available` | Есть ли запись о цене; это не показатель наличия на складе |
| `d`, `day_index` | Обозначение и порядковый номер дня M5 |
| `wm_yr_wk` | Идентификатор недели для соединения с таблицей цен |
| `weekday`, `wday`, `month`, `year` | Календарные признаки |
| `event_name_*`, `event_type_*` | Отмеченные в календаре события |
| `snap_CA`, `snap_TX`, `snap_WI` | Календарные индикаторы SNAP по штатам; наш магазин находится в CA |

## Проверки и ограничения

- Дубликатов товар-магазин-дата: 0.
- Пропусков в продажах: 0.
- Дней с нулевыми продажами: 55.64%.
- Строк без цены: 32781.
- Строк с положительными продажами и отсутствующей ценой: 0.

Нулевые продажи сохранены. Они не позволяют различить отсутствие спроса и отсутствие товара.
Пропущенные цены не заполнялись из будущего. Пропуски календарных событий также сохранены.
При обучении отдельно проверим, какая информация действительно доступна на момент прогноза.

Остатки, закупочные цены и сроки поставки в будущем зададим как допущения симуляции.
Категория FOODS и один магазин ограничивают применимость выводов первой версии.

## Как повторить

Запустить разделы 0–2 ноутбука `notebooks/01_exploration.ipynb` в окружении проекта.
При отсутствии архива первая ячейка раздела 1 скачает его и проверит контрольную сумму.
Исходные CSV, архив и подготовленные таблицы исключены из Git. В репозитории остаются код и документация.
