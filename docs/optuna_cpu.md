# Optuna на Kaggle CPU

Ноутбук: [05_optuna_cpu.ipynb](../notebooks/05_optuna_cpu.ipynb).

Самостоятельный запуск для 67 принятых признаков: 63 прежних и четыре признака цены целевой недели. Старые ноутбуки и checkpoint с ценовыми экспериментами для первого запуска не нужны. Первый поиск выполнен: 29 завершённых попыток, лучший WRMSSE 0.506104 против контроля 0.538018. [Точные результаты](../results/m5_wrmsse/optuna_lgbm_67_cpu_52x8_v1/README.md).

## Первый запуск

1. Импортировать ноутбук 05 в новый Kaggle Notebook.
2. Подключить M5 Forecasting — Accuracy через Input.
3. Выбрать Accelerator → None. Для установки LightGBM 4.6.0 и Optuna 4.5.0 при необходимости нужен Internet.
4. Оставить настройки первого поиска и выбрать Save Version → Save & Run All.

По умолчанию идут один фиксированный контроль на 386 деревьях и до 40 попыток Optuna на **52 × 8**, 12 683 840 строк. Первая попытка использует текущие параметры с большим лимитом деревьев. Предел — 1600 деревьев; остановка после 200 итераций без улучшения WRMSSE. Число потоков — четыре; модели обучаются последовательно. Данные и бины подготавливаются один раз.

Десятичасовой бюджет ограничивает запуск следующих попыток; начатая попытка может закончиться позже. Сборка train и фиксированный контроль входят в этот бюджет. Это ограничение не является обещанием точного времени завершения всего Kaggle-задания.

## Что подбирается

| Параметр | Диапазон |
|---|---|
| learning_rate | 0.025–0.10, логарифмический |
| num_leaves | 31, 63, 127 |
| min_data_in_leaf | 50, 100, 250, 500 |
| lambda_l1 | 0–3 |
| lambda_l2 | 0.1–20, логарифмический |
| feature_fraction | 0.75–1 |
| bagging_fraction | 0.7–1 |
| tweedie_variance_power | 1.1–1.9 |

Функция потерь — Tweedie, оценка и ранняя остановка — WRMSSE на 12 уровнях. `max_bin=255` фиксирован, `feature_pre_filter=False` допускает перебор минимального размера листа на одном Dataset. Дополнительный pruning Optuna не включён.

## Результаты и продолжение

После контроля и каждой завершённой попытки обновляется:

`/kaggle/working/demand-planner_optuna_cpu_checkpoint.zip`

Внутри — SQLite, манифест с версиями и хешами CSV, план, таблица попыток, два финалиста, их модели и прогнозы, фиксированный контроль, параметры и кривые качества. Модели остальных попыток удаляются из рабочего набора; их метрики и протоколы сохраняются.

Чтобы продолжить, подключить ZIP или распакованную историю как Input. Ноутбук автоматически находит архив с точным именем или распакованную папку с `results/` и `models/`. При нескольких копиях указать `RESUME_FROM` в настройках. `TOTAL_TRIALS` — общий бюджет одной истории; чтобы добавить попытки, увеличить его. FAIL после аварийного прерывания тоже занимает попытку.

SQLite не сохраняет внутренний генератор Optuna, поэтому последовательность новых предложений при продолжении может отличаться. Завершённые результаты повторно не считаются. Незавершённая модель целиком не восстанавливается. Изменившиеся данные, версии или протокол требуют новой истории либо восстановления прежних настроек.

Архив в `/kaggle/working` остаётся файлом рабочей среды. После успешного Save & Run All забрать его из Output сохранённой версии. Принудительное завершение среды до сохранения Output может потерять последние несохранённые файлы.

## Как интерпретировать

Окно подбора: 28 марта — 24 апреля 2016 года. Это период разработки. Минимум не является независимой тестовой оценкой или официальным Kaggle score. Новый контроль и Optuna сравниваются на одинаковой выборке 52 × 8. Известный WRMSSE 0.53079 относится к прежней модели 52 × 16; напрямую сравнивать эти числа как эффект параметров нельзя.

Следом проверяем Trial 9 и Trial 5 на 52 × 16, затем финалистов и контроль на других исторических окнах и подтверждённых кандидатов на 52 × 28. Затем — ансамбль, калибровка и итоговый прогноз. Если появился `cap_reached`, проверяем больший лимит деревьев.

При подготовке проверены синтаксис, неизменность базовых функций, план дат, математический расчёт WRMSSE и операции checkpoint на небольших фикстурах. Полный запуск ноутбука, обучение и модельное прогнозирование локально не выполнялись.
