# Demand Planner

Учебный проект: прогноз продаж и планирование закупок при ограниченном бюджете.

Сначала исследуем данные M5 и строим недельный прогноз. Затем добавим планирование закупок, проверку решений на истории и небольшое демо.

## Текущий статус

Данные M5 загружены и проверены. Подготовлена выборка: магазин CA_1, 100 товаров FOODS, одна строка на товар и день. Разделы 0–2 ноутбука готовы; модели и расчёты закупок ещё не реализованы. Описание данных: [docs/data.md](docs/data.md).

## Окружение

Python 3.12. Виртуальное окружение находится в `.venv` и не сохраняется в Git.

Для установки на другом компьютере из корня проекта:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m ipykernel install --sys-prefix --name demand-planner --display-name "Python (demand-planner)"
```

`requirements.lock.txt` фиксирует версии, проверенные при первоначальной настройке на macOS с Python 3.12. Для повторения этого окружения используйте его вместо `requirements.txt`.

## Начальный ноутбук

Запуск из корня проекта:

```bash
source .venv/bin/activate
jupyter lab notebooks/01_exploration.ipynb
```

В ноутбуке выберите ядро **Python (demand-planner)**. В VS Code также можно выбрать интерпретатор `.venv/bin/python`.

## Структура

- `notebooks/01_exploration.ipynb` — исследование данных и первые эксперименты.
- `data/raw/` — исходные данные, которые сохраняем без изменений.
- `data/processed/` — подготовленные таблицы.
- `src/features.py` — будущие функции подготовки признаков.
- `src/train.py` — будущее обучение.
- `src/forecast.py` — будущий прогноз.
- `src/planner.py` — будущее планирование закупок.
- `src/backtest.py` — будущая проверка на истории.
- `models/` — сохранённые модели.
- `results/` — небольшие таблицы результатов и графики.
- `tests/` — будущие проверки признаков и ограничений закупки.
- `app.py` — будущее демо.

## Данные

Источник: [M5 Forecasting — Accuracy](https://www.kaggle.com/competitions/m5-forecasting-accuracy/data).

На первом этапе понадобятся `calendar.csv`, `sell_prices.csv` и `sales_train_validation.csv`. Их нужно разместить в `data/raw/`. Данные, окружение, сохранённые модели и секреты исключены из Git.

В M5 наблюдаются продажи. Остатки, закупочная стоимость и сроки поставки для будущей симуляции будут заданы отдельно; результаты этой части будут зависеть от допущений.
