# Demand Planner

Учебный проект: прогноз продаж и планирование закупок при ограниченном бюджете.

Сначала исследуем данные M5 и строим недельный прогноз. Следующий этап — дневной прогноз на 28 дней и оценка по метрике Kaggle M5. После улучшения прогноза добавим симуляцию закупок и демо.

## Текущий статус

В [первом ноутбуке](notebooks/01_exploration.ipynb) завершён недельный пилот на 100 товарах FOODS магазина CA_1: подготовка данных, EDA, простые методы, CatBoost и проверка по времени.

Во [втором ноутбуке](notebooks/02_scaling.ipynb) завершён эксперимент на всех **3 049 товарах CA_1**. Проверены 27 признаков, четыре временных окна и небольшой подбор параметров Optuna. После выбора настроек модель оценена на четырёх новых неделях: **25 апреля — 22 мая 2016 года**.

| Метод | MAE, единиц на товар за неделю | WAPE | Bias |
|---|---:|---:|---:|
| Среднее за 4 недели | 3.8097 | 34.67% | −3.65% |
| CatBoost после Optuna | 3.5512 | 32.31% | −5.84% |

Снижение MAE — **6.79%**. Модель лучше выбранного бейзлайна во всех четырёх неделях и трёх категориях, но занижает суммарный объём продаж. Это результат одного магазина и короткого периода, а не установленный предел качества.

Модель во время проверки фиксирована. Каждую следующую неделю прогнозируем после завершения предыдущей, обновляя лаги её фактическими продажами. Недельный результат не является Kaggle score: у M5 другая частота, горизонт и метрика.

Финальные [метрики, прогнозы и параметры](results/ca1_scaling/final_test) сохранены в репозитории. Модель `models/catboost_ca1_final.cbm` и история Optuna `models/ca1_optuna.sqlite3` остаются локально и исключены из Git. Результаты пилота сохранены отдельно в [results/weekly_pilot](results/weekly_pilot).

Создан [третий ноутбук](notebooks/03_kaggle_wrmsse.ipynb): постановка дневного прогноза на 28 дней, даты проверки, окружение и структура 12 уровней M5. Начальные ячейки пока не выполнены; реализация WRMSSE, дневные бейзлайны и модели — следующий шаг. Полный конкурсный скор ещё не рассчитан.

Апрель–май уже используются при разработке. Период **23 мая — 19 июня 2016 года** резервируется для следующей итоговой проверки по опубликованным организаторами данным. Описание исходных данных: [docs/data.md](docs/data.md).

## Окружение

Python 3.12. Виртуальное окружение находится в `.venv` и не сохраняется в Git.

Для установки на другом компьютере из корня проекта:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m ipykernel install --sys-prefix --name demand-planner --display-name "Python (demand-planner)"
```

`requirements.lock.txt` фиксирует текущее окружение macOS с Python 3.12, включая Optuna. Для повторения этих версий используйте его вместо `requirements.txt`.

## Ноутбук

Запуск из корня проекта:

```bash
source .venv/bin/activate
jupyter lab notebooks/01_exploration.ipynb
```

В ноутбуке выберите ядро **Python (demand-planner)**. В VS Code также можно выбрать интерпретатор `.venv/bin/python`.

## Структура

- `notebooks/01_exploration.ipynb` — завершённое исследование на 100 товарах.
- `notebooks/02_scaling.ipynb` — завершённый недельный прогноз для CA_1, признаки, Optuna и финальная проверка.
- `notebooks/03_kaggle_wrmsse.ipynb` — начало работы с дневным прогнозом на 28 дней и WRMSSE.
- `data/raw/` — исходные данные, которые сохраняем без изменений.
- `data/processed/` — подготовленные таблицы.
- `src/data.py` — загрузка данных, дневная и недельная таблицы.
- `src/features.py` — недельные признаки, простые прогнозы и разбиение по времени.
- `src/train.py` — будущее обучение.
- `src/forecast.py` — будущий прогноз.
- `src/planner.py` — будущее планирование закупок.
- `src/backtest.py` — расчёт MAE, WAPE и Bias на одинаковых строках.
- `models/` — сохранённые модели.
- `results/` — небольшие таблицы результатов и графики.
- `tests/` — проверки недельной агрегации, доступности истории и метрик.
- `app.py` — будущее демо.

## Данные

Источник: [M5 Forecasting — Accuracy](https://www.kaggle.com/competitions/m5-forecasting-accuracy/data).

На первом этапе понадобятся `calendar.csv`, `sell_prices.csv` и `sales_train_validation.csv`. Их нужно разместить в `data/raw/`. Данные, окружение, сохранённые модели и секреты исключены из Git.

В M5 наблюдаются продажи. Остатки, закупочная стоимость и сроки поставки для будущей симуляции будут заданы отдельно; результаты этой части будут зависеть от допущений.
